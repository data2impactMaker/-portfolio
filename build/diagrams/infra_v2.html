이벤트 로그 설계 프레임워크

기능 목록에서 출발하던 로그 설계를 비즈니스 질문에서 출발하도록 바꿨습니다

요구사항 정의서와 유저플로우 링크만 넣으면 KPI 체계와 화면×이벤트 설계안이 표준 양식으로 나오고, 자료로 알 수 없는 것만 확인 요청으로 돌아옵니다.

01설계 출발점

현행
출발: 화면에 있는 버튼·요소 목록
수집 범위: 요소별 전수 수집
KPI 연결: 수집 후 사후에 찾음
프레임워크 적용 후
출발: 비즈니스 질문과 가설
수집 범위: KPI에 직결되는 이벤트만
KPI 연결: 질문당 KPI 1개, 본부 지표에 연결

02설계 과정

현행
이름 규칙: 담당자마다 제각각
기존 이벤트: 있는지 모른 채 새로 만듦
검증: 적재 후 수기 확인
프레임워크 적용 후
이름 규칙: view·click 2종, 의미는 파라미터
기존 이벤트: 정본 조회 후 재사용 우선
검증: 등록 전 자동 lint, 실제 수집 여부 조회

03산출물과 소통

현행
산출물: 엑셀 표, 문서마다 양식 다름
빈칸 처리: 추측으로 채움
소요: 설계 회의 여러 차례
프레임워크 적용 후
산출물: 표준 양식(KPI 체계·화면×이벤트·등록안)
빈칸 처리: 확인 필요 목록으로 되물음
소요: 자료 링크 입력 후 설계안 즉시 생성
데이터마트 · Git 기반 지표 SSOT

지표와 이벤트 정의를 한 곳에 두고, 모든 화면이 같은 정의를 읽습니다

리포트마다 산식이 달라 숫자가 어긋나던 문제를 정의의 단일 원천으로 풀었습니다. 지표는 BigQuery 마트 한 곳, 이벤트는 Git 마스터 한 곳에서만 정의하고, 대시보드·리포트 봇·슬랙봇·에이전트가 그 정의를 그대로 가져다 씁니다.
원천
운영 데이터와 로그
결제·주차장·회원 DB, GA4·Amplitude 행동 로그, 날씨·공휴일 외부 데이터
적재 · 변환
Airflow + dbt
원천을 마트로 정기 변환. 배포 전 DAG·모델 파싱 검증
단일 원천
BigQuery 마트 · Git 정의 저장소
지표 산식은 마트에, 이벤트 정의는 event_master.yaml에. 등록 전 lint가 규칙을 검사하고 변경은 PR로 남습니다
소비처
같은 정의를 읽는 화면들
마케팅 대시보드, 리포팅·감시 봇 15종, 슬랙봇 모케터, AI 분석 에이전트
정의 항목어디에 있나무엇을 막나
지표 산식BigQuery 마트 테이블 · 공용 SQL 13종리포트마다 다른 숫자
이벤트 이름·파라미터이벤트 마스터 134건 · 값 체계 룰 14종같은 행동을 다른 이름으로 수집
변경 이력Git PR · CODEOWNERS 리뷰누가 왜 바꿨는지 모르는 정의
등록 검증lint 자동 검사 · 오류면 배포 차단규칙 위반 이벤트의 유입
정의를 바꿀 때
  • 설계 요청: 새 지표나 이벤트가 필요해지면
  • 에이전트 설계: 정본을 조회해 재사용 여부를 먼저 판단
  • lint 검증: 이름 규칙·값 체계·중복을 자동 검사
  • PR 리뷰·머지: 담당자 리뷰 후 정본 반영
  • 즉시 적용: 모든 소비처가 새 정의를 읽음
CRM 분석 · 의사결정 통합 저장소

캠페인의 기획, 실행, 분석, 결정을 한 폴더에 쌓습니다

저장소가 곧 운영 데이터입니다. 사람이 만든 문서든 에이전트가 만든 분석이든 같은 자리에 들어가고, 슬랙봇·대시보드·에이전트는 그 파일을 직접 읽어 같은 숫자와 같은 맥락으로 답합니다.

campaigns/ 캠페인마다 한 폴더
  기획서 목적 · 타겟 · 실험 설계
  세팅 가이드 카피 · 미리보기 · 발송 조건
  분석 보고 실험군 대비 대조군 · 퍼널
  카드 상태 · KPI · 대조군 비율
knowledge/ 정책 · 가이드 · 운영 규칙
approvals/ 검토 요청과 승인 기록
recommendations/ 주간 추천과 채택 · 비채택 사유
📂
저장하면 끝
기획서를 폴더에 넣는 순간 대시보드 카드가 생기고 슬랙봇이 같은 문서로 답합니다. 따로 등록하는 일이 없습니다
🧭
결정의 이유가 남는다
누가 왜 채택했는지, 어떤 후보를 왜 보류했는지가 캠페인 옆에 기록됩니다
🤖
AI가 맥락을 읽는다
에이전트가 과거 기획과 분석을 직접 찾아 읽고 다음 캠페인을 설계합니다. 검색 색인을 따로 두지 않습니다

이 저장소 위에서 다음에 할 수 있는 것

  • 주간 추천의 자기 학습: 채택·비채택 사유와 성과가 쌓이면 다음 주 추천 점수가 그 결과를 반영한다
  • 성과 예측: 같은 양식으로 쌓인 수백 건의 기획·결과를 근거로 발송 전에 기대 순증을 제시한다
  • 기획안 자동 초안: 비슷한 과거 캠페인을 찾아 목적·타겟·소재를 채운 초안을 먼저 내놓는다
